- **Proposed fix item (bug), `dockerfile-run-exit-status`.** Not filed: an
  unattended run cannot use workflow-intake.
  - The problem: `driver/script/translate.go` writes each RUN verbatim into one
    `#!/bin/sh` + `set -e` script. Under `set -e` a failure inside an `&&` or
    `||` list does not exit, so `RUN wget ... && echo ok` and similar keep
    going. Seen here: a qemu build reported SUCCEEDED after `wget` and
    `apk add jq` failed. Docker fails such a RUN.
  - The fix: run each RUN as its own `sh -c` (or `( ... ) || exit $?`), with a
    translate test.
  - Scope: the VM drivers that take a Dockerfile (qemu, hyperv, vz).
- **Proposed cleanup item, `vz-deadcode-removal`.** Remove the 10 unreachable
  driver/vz functions listed above, or say why they stay (FLOW-15).
  - `make integration-test-vz` runs `TestRelayVMBoot`, which does not exist
    in driver/vz. The target passes vacuously, so it needs a real test or
    removal.
- **Docs mismatch.** `docs/book/src/guide/drivers.md` says qemu caches images
  in `~/.cache/warden/images/`, but on macOS it uses
  `~/Library/Caches/warden/images/` (`os.UserCacheDir`). vz uses
  `~/.cache/warden`. A small doc fix, or make the two drivers agree.
