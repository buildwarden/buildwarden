# `http-headers` metadata schema, v1

| | |
|---|---|
| `$id` | `https://github.com/buildwarden/buildwarden/schemas/v1/http-headers.json` |
| Machine schema | [`metadata-http-headers/v1.schema.json`](https://github.com/buildwarden/buildwarden/blob/main/specs/metadata-http-headers/v1.schema.json) |
| Applies to | `checkpoint` records whose payload is HTTP request or response headers |
| Default header index | 1 (see the ledger spec's [Default Schemas](../build-ledger/v1.md#default-schemas)) |

## Purpose

Surfaces the headers a reader is likely to care about without parsing the raw
header bytes, which are the record's payload. Credentials never appear in it.

## Fields

```cbor
{
  "headers": [
    ["X-Amz-Request-Id", "abc123"],
    ["X-Custom-Header", "value"],
    ["Authorization", "<redacted>"],
    ["Cookie", "<redacted>"],
    ["Set-Cookie", "<redacted>"]
  ]
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `headers` | array of [name, value] | yes | Non-standard headers, each a two-element array of text. Auth-related headers (`Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization`) are listed with value `<redacted>`. Standard/structural HTTP headers (those defined in HTTP/1.1 and HTTP/2 base specifications) are omitted — they exist in the raw payload bytes. |

No other fields are allowed.
