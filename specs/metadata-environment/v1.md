# `environment` metadata schema, v1

| | |
|---|---|
| `$id` | `https://github.com/buildwarden/buildwarden/schemas/v1/environment.json` |
| Machine schema | [`metadata-environment/v1.schema.json`](https://github.com/buildwarden/buildwarden/blob/main/specs/metadata-environment/v1.schema.json) |
| Applies to | The [environment record](../build-ledger/v1.md#environment-record)'s `open` and `close` |
| Default header index | 5 (see the ledger spec's [Default Schemas](../build-ledger/v1.md#default-schemas)) |

## Purpose

Informational, **unsigned** context on the environment record. The signed
environment payload names its own type and is described by its
`environment-<type>` document; this metadata only echoes it. Readers take the
type from the payload, never from this metadata.

Ledgers written before typed environments use the legacy
[`environment-container`](../metadata-environment-container/v1.md) schema
in this position instead.

## Fields

```cbor
{
  "type": "oci-image/v1",
  "reference": "docker.io/library/python:3.12-slim",
  "digest": "sha256:<64 hex>",
  "mediaType": "application/vnd.oci.image.manifest.v1+json"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | text | yes | `"environment"` on the open record; on the close record an echo of the payload's environment type, such as `oci-image/v1` or `vm-disk-chain/v1` (unsigned; the payload is authoritative) |
| `driver` | text | no | [`vm-disk-chain/v1`](../environment-vm-disk-chain/v1.md): the driver that booted the environment |
| `reference` | text | no | [`oci-image/v1`](../environment-oci-image/v1.md): image reference as the user gave it |
| `digest` | text, `sha256:<64 lowercase hex>` | no | `oci-image/v1`: registry digest of the pulled reference. Equals `sha256(payload)` only when the runtime returned the registry's exact manifest bytes |
| `mediaType` | text | no | `oci-image/v1`: manifest media type |

The schema allows other fields.
