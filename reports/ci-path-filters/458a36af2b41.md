## Tier 2 findings

### MUST

1. **TEST-02** (TEST-01), `.github/workflows/main.yml:45`.
   - **What's wrong:** Go code under `docs/` is classified as docs-only.
     - `docs/*)`, `docs/book/*)` and `docs/development/*)` match every file type.
     - So a PR that adds or edits a `.go` file (or a `go.mod`/`go.sum`) under `docs/` skips lint, tidy and build. It also skips `test` and `tier1-test`, unless the file is under `docs/development/`.
     - The root module's `go test ./...`, `golangci-lint run` and `go vet` compile every package under `docs/`. A broken file there passes the PR and turns the first push to `main` red. Shown in a scratch repo.
     - Decision 2's reason, "No Go package lives under `docs/`", describes today's tree, and a PR can change that. The design's own principle is that anything not positively known to be docs runs the full set.
     - Tier 1 runs on such a PR, but it does not compile packages.
   - **Suggested fix:**
     - Add a first case arm: `*.go|go.mod|go.sum|go.work|*/go.mod|*/go.sum|*/go.work) code=true ;;`. In `case`, `*` crosses `/`. Another option is to narrow the docs arms to the file types `docs/` actually holds.
     - Add the case to the phase-3 classifier table and one line to Decision 2. This keeps Decision 2's intent, so it is not a redesign (FLOW-06).

### SHOULD

1. **TEST-02** (UX-01), `.github/workflows/main.yml:47`.
   - **What's wrong:** `CONTRIBUTING.md` is input to the book, but changing it does not set `book`.
     - `docs/book/src/contributing/development.md:2` is `{{#include ../../../../CONTRIBUTING.md}}`.
     - Root `*.md` files are classified as plain docs, so a PR that changes only `CONTRIBUTING.md` runs no book build. Decisions 2 and 7 list the book's input as `docs/book/**` only.
     - mdBook probably reports a broken include as an error message and still builds, so the build risk is small. The main problem is that the design's table is inaccurate.
     - `docs.yml` has the same gap on `main`: the published Development page goes stale until the next `docs/book` change. That predates this change, and the design leaves `docs.yml` alone on purpose.
   - **Suggested fix:**
     - Add `CONTRIBUTING.md) book=true ;;` before the `*.md)` arm, and update Decision 2's table to match.
     - Raise adding `CONTRIBUTING.md` to the `docs.yml` paths as a separate small item.

### Hints

- **`main.yml:38`, TEST-02.** `git diff` quotes non-ASCII paths. A quoted path falls through to code, which is fail-open for the Go jobs, but a non-ASCII-only `docs/book/` change gets no book build. Fix: `git -c core.quotePath=false diff ...`.
- **`main.yml:168`, GLOBAL-06.** The `book` checkout keeps the token in `.git/config` while it runs an mdBook binary that is downloaded without a hash check. The token is read-only, and `docs.yml` does the same. Add `persist-credentials: false`, and optionally a `sha256sum -c`.
- **`main.yml:57`, TEST-02.** The `if:` lines test `== 'true'`, so a missing output would mean skipped, and ci-ok passes on skipped. No current path produces that: every exit writes all three outputs, and under `bash -e` a failed write fails the step. `!= 'false'` would make fail-open hold by construction.
