## Code, design and reference agree

- **Regular file.** Decision 14, **How the config file is found**, the row in
  **Defaults and overrides** and Security note item 10 all say the same thing:
  - A `./warden.toml` found by default that is not a regular file, once links are followed, is the error `not a regular file` and is not opened.
  - A link to nothing counts as no file.
  - A named file is read whatever kind of file it is.

  In the code, `readConfigFile` (`cmd/warden/config.go:175`) raises
  `errNotRegular` only for `configFromDir`, after an `os.Stat` that follows
  links. `configFile` treats `ErrNotExist` as no file.
  `configuration.md:28-34` and `overview.md:32-35` say the same.
- **Cap.** The code matches the design:
  - `maxProjectConfig = 1<<20` and `configBlock = 1<<16`.
  - `readCapped` (`config.go:252`) returns `errTooLarge` once `len(data) > 1048576`, so it reads at most 1114112 bytes.
  - Any other read error is returned unchanged, with the unreadable-file text and fix.
  - The over-cap error has the design's text and fix line.
  - Named sources use `os.ReadFile`, so they have no cap.

  The tests cover every case the Validation plan lists: exactly 1 MiB, 1 MiB
  and one byte, `/proc/self/pagemap`, `/proc/self/mem` (EIO), endless readers
  bounded at the cap plus one block, a read that fails before the cap, and
  over-cap files named with `--config` and with `WARDEN_CONFIG`. The verifier
  ran these cases under all six commands that read configuration, and the
  results agree.

## Judged and not findings (noted for the human)

- The fix line for `not a regular file` is the unreadable-file fix ("make it readable, ..."). The design's example gives exactly this text.
- **Window between stat and open in `readConfigFile`:** a `./warden.toml` replaced by a FIFO after `os.Stat` would block `os.Open`.
  - Exploiting it takes a concurrent writer on the host, which is outside the design's model of a static repository, and no rule covers it.
  - Checking the opened file (`f.Stat()`, or opening with `O_NONBLOCK`) would close the window.
- **`driver/detach.go` passes the parent's config path to the background `image prepare` as `--config`** (Decision 10).
  - When the parent read the default file, the child reads that path as a named file: with no cap and no regular-file check.
  - This only matters if the file is replaced between the two reads, which is the same race-only class as above.
- **GLOBAL-10 and GLOBAL-11:** the cap is not a fallback. A file over it is an error, not a partial read and not a switch to another source, as the design states. No default or merge appears that the section does not list.
- **UX-01 and FLOW-15:** the reference and `overview.md` change with the code.
- The design's edits after `b7ddd0e` are only the r3 plan delta and the approval record.
- **TEST-01 and TEST-04:** the procfs cases skip with a reason where the platform cannot run them. `readCapped`'s cases use in-memory readers and run on every OS.
