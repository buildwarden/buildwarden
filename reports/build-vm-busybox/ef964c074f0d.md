### 1. UX-04 (with GLOBAL-11), SHOULD: `tools/build-vm/build-initramfs.sh:50`

On a checksum mismatch the script stops (set -e) with only sha256sum's or shasum's own output ('busybox-static-1.37.0-r14.apk: FAILED', 'WARNING: 1 computed checksum did NOT match'). It does not say which file to remove or that the pin may need changing. The bad apk stays in tools/build-vm/.cache/, so every rerun fails the same way. Validation plan case 2 (a corrupted cached apk) exercises exactly this path. tools/firecracker-vm has the same gap on main; it is out of this diff's scope (LINT-04) and not filed separately.

**Suggested fix:** Wrap the check: on failure print 'Error: $CACHE_DIR/$BUSYBOX_APK does not match BUSYBOX_SHA256; delete it and rerun, or re-pin both direct-boot scripts if Alpine republished it' and exit 1. Align the Firecracker copy at its next re-pin, when its cache key changes anyway.

### 2. UX-04 (with GLOBAL-11), SHOULD: `tools/build-vm/build-initramfs.sh:42`

Any curl failure (offline host, DNS, a proxy refusal, a 5xx) is reported as 'Alpine 3.21 no longer has busybox-static-1.37.0-r14.apk; set BUSYBOX_VERSION and BUSYBOX_SHA256 ... to the current busybox-static'. That names a cause that may be wrong and a fix that does not help. This feature's own q1 is the case: the cloud proxy refused dl-cdn.alpinelinux.org, and this message would have told the user to re-pin. The fix also names only $0, while TestDirectBootBusyboxPins requires both direct-boot scripts to move together. The text is copied from tools/firecracker-vm (main).

**Suggested fix:** State what failed and branch the fix: 'Error: could not download ${ALPINE_MIRROR}/${BUSYBOX_APK} (curl's error above). Check network access to dl-cdn.alpinelinux.org; if v3.21's APKINDEX no longer lists it, re-pin BUSYBOX_VERSION and the per-arch BUSYBOX_SHA256 in tools/build-vm and tools/firecracker-vm'. Optionally, curl -o /dev/null -w '%{http_code}' could tell a 404 from a network failure.
