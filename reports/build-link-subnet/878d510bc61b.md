### 2. UX-09 (with UX-04), SHOULD: `cmd/warden/host.go:260`

Implement item 3. Doctor prints the link, its source, the host overlap and each stamp, and exits non-zero only on a host-interface overlap. That matches Decision 8's list of what doctor prints. But doctor's own contract (host.go help, cli.md) is 'exits non-zero when a required capability is unmet, so it is usable as a CI or agent gate'. On hyperv (relay boot VHDX) and vz (the prepared image), the stamped asset is required by every build, so a missing or stale stamp means every build refuses while doctor exits 0. On qemu and firecracker the stamped initramfs serves only direct boot, so a report is enough there.

**Suggested fix:** Exit non-zero when a stamp is missing or stale on an asset every build of that driver needs (hyperv, vz). Keep the qemu and firecracker direct-boot stamps as reports. Or record the reason for not doing so in the design at Consolidation.

### 3. UX-04, SHOULD: `driver/vz/driver.go:455`

Implement item 8. With `--image /path/disk.img`, the stamp is looked up beside that disk, which is the right place. But the refusal's fix is PrepareCommand (`sudo warden image prepare --driver vz`), which re-prepares only the default cache's image (cmd/warden/image.go prepareVZMacos). A user with a custom image follows the fix and is refused again: a dead end on an uncommon path.

**Suggested fix:** When the disk is outside the cache, name a fix that works for that path: re-prepare that image directory, or omit --image to use the prepared cache image. Or let `image prepare --driver vz` take the image directory, if a one-line ReprepareImage(dir) path is wanted. Add a table case to TestImageStamp.

### 4. GLOBAL-04 (with TEST-01, TEST-02), SHOULD: `cmd/relay/buildif_linux.go:148`

Implement item 9. buildif_linux.go (rtnetlink dump parsing, RTM_NEWADDR/DELADDR encoding, ack handling) and dhcp_vm_linux.go (SO_BINDTODEVICE on udp/67) have no tier-0 tests. Their callers are well covered through the buildIface and packetConn fakes (vmlink_test.go, dhcp_test.go incl. FuzzDHCPReply). Opening sockets needs root and a netns, so the syscalls belong to tier 2 and native validation (the firecracker CI run and the linux-kvm and qemu-any hosts), as TEST-01 intends. The parsing and encoding are pure, though, and are where a silent bug would hide: parseRoute's RTA_DST/RTA_OIF handling, the IFA_LOCAL-over-IFA_ADDRESS choice, and the ifaddrmsg layout. A related edge: Flush deletes addresses one by one from a single dump, and on Linux deleting a primary address also deletes its secondaries in the same subnet (promote_secondaries off). The next RTM_DELADDR then fails with EADDRNOTAVAIL and the claim fails with 500. Unlikely with today's inits, which add one address.

**Suggested fix:** Split the message building and parsing from the socket I/O. Test them at tier 0 with canned netlink bytes: a dump holding a default route, a /30 route on another oif and a multi-address interface, plus addrRequest's encoded bytes. In Flush, treat EADDRNOTAVAIL as already removed.

### 5. GLOBAL-04 (with ORCH-01, TEST-05), SHOULD: `driver/vz/driver.go:237`

Implement item 6. Only Hyper-V has an end-to-end tier-0 test that its claim carries the link. qemu (driver.go:221), firecracker (driver_linux.go:218) and vz (driver.go:237) each pass `req.Link().Claim()` in one line, with no test. driver/session_link_test.go covers ClaimRelay sending what it is given. At minimum cover vz, the quiet case.

### 7. UX-01 (with UX-08), SHOULD: `docs/book/src/guide/configuration.md:101`

Implement item 7. A malformed `[vm] build_link` fails every command, container builds included, because it is checked as the file loads (cmd/warden/config.go:128). That behaviour is right: Decision 8 says 'a config value is checked when the file loads', and UX-08 favours failing fast on a bad config whatever the driver. It is not a redesign, since a17 is about the claim, not the key. But the reference doc says only 'The container driver ... ignores the setting', which reads as if a bad value is ignored there too.

**Suggested fix:** Keep the behaviour. Reword configuration.md:101 to say the container driver ignores a valid value, and that a malformed one is refused at load by every command (as any config error is).

### 8. UX-04, SHOULD: `tools/relay-vm/hyperv/refresh-cache.sh:42`

refresh-cache.sh exits 'relay boot VHDX is current' when the disk exists and relay-boot.source matches. It does not check whether relay-boot.link-channel exists. The source stamp excludes the script itself, so a disk whose link stamp is missing but whose relay source matches is never re-stamped. warden refuses it, naming refresh-cache.sh, and refresh-cache.sh says it is current: a loop. It cannot happen on this branch's own history, since the stamp line landed with relay-source changes in 19bbe69 and relay changed again later. It can happen if the stamp file is lost, or a disk is copied without it.

**Suggested fix:** Require the link stamp for the 'current' short-circuit (`[ -f "$linkf" ]`, and `--check` reports it). Or have warden's fix for a missing stamp say `refresh-cache.sh --force`.
