## Findings

### 1. TEST-04 (MUST), fixed at buildwarden-specs 4d95ad85552e (found at 34121cc7874a)

`conformance/launch/relay_test.go:265` and `:297`. Every case now has a one-minute limit, which only bounds a
failure. In "run exited", `in.done` is closed before the call, so the outcome no longer depends on timing.
The two timeout cases cancel a parent context once the fake's call count passes the number of answers.
The fake increments the count before it answers, and `containerPID` inspects one call at a time. So the
cancel comes only after the last answer has been read and `listed` recorded. Every path then leads to
`ctx.Done`, and the asserted message's `1m0s` is the limit argument, not elapsed time. The `fired` check
fails a case only if the one-minute bound ran out. No wall-clock is left in what an assertion checks.
